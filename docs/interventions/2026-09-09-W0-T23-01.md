## What the agent proposed

Remove the shared files that parallel branches collide on, by splitting each into one file per
record: `apps/web/src/i18n/locales/{es,en}.ts` became twelve namespace files plus two barrels and a
`Mirror` helper; `memory/repo/*.md` and `memory/slices/*.md` became 41 files with frontmatter, with
`memory/LONG_TERM.md` and the README Layout table generated from them; `pnpm-lock.yaml` and the
generated index got git merge drivers that resolve by recomputing.

2611 insertions across 124 files. Merged as `bb1c2ee`, then reverted.

## What was wrong

**The trade-off was never put to the operator, and it is not the one they want.** The operator's
position, stated after merging:

> The solution proposed for conflicting files is no good: how does duplicating UI elements per
> translation is a correct choice? I prefer having to rebase some branch manually, then getting
> this kind of patches.

Two files of translations became fourteen, each `en/<ns>.ts` importing its `es/<ns>.ts` counterpart
to stay type-checked. That is a permanent, every-day cost paid by every agent reading or editing
copy, to avoid an occasional merge conflict that a human resolves in under a minute. The same
objection applies to 41 memory files replacing four.

The work was correct against its spec and its acceptance criteria — `tests/parallel-merge.test.ts`
genuinely proves two branches merge clean. **The spec was the wrong spec.**

## Root cause

spec-gap

The spec asserted the direction as settled and moved straight to design. Issue #153 had proposed
options A–E with a recommended order, and the spec adopted that ordering without ever asking whether
the restructuring was worth its standing cost. Its risks section argued the *residual* collisions
(the barrel still changes once per slice) but never the premise. Nothing in the pipeline forces that
question, so ~2600 lines landed before a human saw the shape of the result.

Reading it as `model-error` is defensible — the agent chose the design — but that framing produces
no corrective action, and the missing checkpoint does.

## What was done instead

Reverted on `main`. The pre-existing layout is restored: two translation catalogues, four appended
memory files, and manual rebasing when branches collide.

**One change was deliberately kept out of the revert**: `turbo.json`'s
`"@marketplace/config#lint": { "dependsOn": ["build"] }`. It fixes a cold-cache CI failure that
predates `W0-T23`, is unrelated to the rejected design, and — because the revert removes four root
`package.json` scripts and so invalidates turbo's global hash — the revert PR itself would have gone
red without it. Kept with its regression test and `MEM-2026-09-09-27`.
