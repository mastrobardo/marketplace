# `pnpm <binary>` is a script lookup, not an exec

**Fact.** `pnpm tsx foo.ts` makes pnpm look for a **script** called `tsx` and fail with `Command
"tsx" not found` / `Did you mean "pnpm test"?`. Running a binary from `node_modules/.bin` needs
`pnpm exec tsx`. Separately, a binary that is a devDependency of one workspace member is not on
the root's PATH — `tsx` belonged to `apps/api` and had to be added at the root.

**Why.** The error names a missing command, so it reads as a missing dependency rather than as the
wrong invocation, and the suggested fix ("did you mean pnpm test") points nowhere useful.

**Apply.** In a workflow or a root script, always `pnpm exec <bin>`. The repo's older root scripts
use `node --experimental-strip-types`, which does **not** work for a module with relative imports:
it resolves `./config.js` literally and cannot find the `.ts` file. Use `tsx` for anything with
imports.
