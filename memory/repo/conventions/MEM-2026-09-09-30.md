# A file two agents change on the same day is a design defect, not a merge problem

**Fact.** The fix for a recurring conflict is to remove the shared structure — one record per file,
one i18n namespace per file — or to make the file **generated** so a conflict is resolved by
recomputing it. A merge driver is legitimate only where the file is a pure function of inputs that
cannot themselves conflict, because the merge result is then discarded rather than stitched.

**Why.** Trivial conflicts scale O(n²) in open branches, and for an agent a conflict is a stop, not
a shrug. But automating the *merge* of a hand-written file is worse: a keep-both script run on
PRs #150/#151/#152 was right on five hunks and wrong on two, because the README Layout table looks
append-shaped and is really a modification.

**Apply.** Before adding a file every agent will touch, give each agent its own file instead. Never
put a merge driver on hand-written prose — `README.md` deliberately has none. Run
`./scripts/setup-git.sh` once per clone to register the drivers that do exist.
