# `satisfies` stops catching excess keys the moment the object is built from spreads

**Fact.** TypeScript's excess-property check applies to **direct object literals** only. `const x =
{ ...a, ...b } satisfies Shape` still reports a *missing* key but silently accepts a key `Shape`
never declared, because the spread launders it.

**Why.** Excess-property checking is a freshness rule on literal types, and a spread result is not
fresh. Nothing warns, so the assertion reads as if it enforces both directions when it enforces
one.

**Apply.** Put the `satisfies` on the smallest direct literal you can — per source file, before
composition. `apps/web/src/i18n/locales/en/*.ts` does this per namespace rather than once on the
composed barrel, which is what makes an invented translation key a compile error.
