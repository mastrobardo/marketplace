# Turbo's `^build` is upstream-only, so a package that consumes its own `dist/` is unordered

**Fact.** `"dependsOn": ["^build"]` orders a task after the builds of a package's **dependencies**,
never after its own. `packages/config/eslint.config.js` imports `./dist/eslint.js`, and
`@marketplace/config` has no upstream, so `@marketplace/config#lint` had nothing ordering it after
`@marketplace/config#build`. Fixed with a package-specific override, `"@marketplace/config#lint":
{ "dependsOn": ["build"] }` — no caret.

**Why.** It only fails on a **cold** cache, and the cache is warm almost always. Any edit to the
root `package.json` invalidates turbo's global hash, so an unrelated change to a `scripts` entry is
what finally surfaced it — green locally, red in CI, with a stack trace naming `dist/eslint.js` and
nothing about task ordering.

**Apply.** Reproduce a suspected turbo ordering bug with `rm -rf packages/*/dist .turbo` before
believing a green local run. Any config file loaded as JavaScript that imports its own build output
needs a self-referential `dependsOn` — the caret is the bug.
