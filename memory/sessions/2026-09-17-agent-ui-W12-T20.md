## The findings worth remembering

**A class name is a string in the JS and a selector in the CSS.** The build assertion's first
version searched for the bare CSS Modules hash and reported 8 of 67 missing on a build containing no
component CSS at all — it was measuring tree-shaking. With a leading `.` it reported 67 of 67.
A wrong gate that names specific missing subjects looks more trustworthy than a passing one.
(`MEM-2026-09-17-1`.)

**Every gate can be working while nothing is watching the product.** Axe is green on an unstyled
page; the story baselines are green because Storybook loads the stylesheet; the test that reads the
entry point's imports was satisfied by the tokens line. Seven page tickets shipped over it.
(`MEM-2026-09-17-2`.)

**Derive the subject list even when you are certain it has one entry.** `pnpm dev` was going to be
fixed for `@marketplace/ui`; the derivation immediately found `@marketplace/contracts` too.

**An accept path is part of a gate.** `visual-baselines.yml` could regenerate stories, on `main`.
A ticket that introduces a route has neither. Adding a gate without asking how its baselines are
first produced ships a permanently red check.

**`import.meta.url` is an http URL under jsdom** — filesystem assertions need
`// @vitest-environment node`, which is why the route coverage is its own file.
