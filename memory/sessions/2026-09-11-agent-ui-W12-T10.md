## The findings worth remembering

**Two `role="search"` landmarks on one page.** The shell's header already puts one on every page, so
the hero is the second — the case `SearchBar.tsx`'s comment predicted for `W12-T11`, a ticket early.
Same role + same name = an axe failure and a screen-reader user hearing "search" twice. The hero gets
`search.hero.label`.

**The header had been navigating to `/es/search?` with an empty query string** since `W12-T09`.
`SearchBar` reports `isRequired` and lets the form submit by design (`validationBehavior="aria"`) —
the sentence is the application's to own, and the application had not owned it. Found by writing the
hero's version of the test. The guard is now one hook both bars call, because two renderings of one
declaration that disagree about validity is the exact drift `W12-T07`/`W12-T09` exist to prevent.

**A section with a heading over an empty list is worse than no section.** `GET /categories` is still
`W3-T01`, so the degraded path is the normal path. Absent, not empty — and an empty list and a failed
request must produce the same page.

**A child route gets its own loader on the parent's query key**, not `useRouteLoaderData`. R3 holds by
construction, the warm cache makes the second call free, and the pattern still works for the pages
whose data the shell does not happen to have.

**A design system component may not decide that a caller's content is decorative.** First `Card` drew
`aria-hidden` on the eyebrow because the first caller's eyebrow is an ordinal an `<ol>` already
announces. Correct reasoning, wrong owner — it moved to the call site.
