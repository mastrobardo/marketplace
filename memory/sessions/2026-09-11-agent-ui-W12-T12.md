## The findings worth remembering

**The ticket named four things that have no columns.** Gallery, badges, reviews and "listing detail"
are in `TODO.md` §3's domain sketch and in no migration. Reading `schema.prisma` before planning is
what turned this from a build into a scoping decision — and it is the second consecutive ticket where
the backlog described a route or an endpoint that could not exist.

**A 404 was being retried.** `retry: 1` applied to every failure, so a dead link showed a blank
screen for a retry delay before saying anything. 4xx is an answer, not a transient fault. Fixed in
`shared/query.ts`, which fixes the shipped search page too.

**Then the same retry made a test pass for the wrong reason.** One stubbed rejection never reached
the error boundary — React Query consumed it and the second call succeeded. A mock has to outlast
the retry policy or the assertion is about something else. Third occurrence of the family in
[[marketplace-ci-gates-fail-open]]: a green result whose run was not the run being asked about.

**`aria-labelledby` pointing at an id with spaces in it leaves a `<section>` with no role.** The
three pending sections were `div`s to the accessibility tree and pixel-identical. `useId`, always —
never an id built from a translated string.

**`.omit().extend()` keeps a `strictObject` strict in zod 4**, which is what let the profile be
derived from the search result instead of retyped. The privacy refinements come along for free.

**A loader should never read `error.response.status`.** `ApiError` in `shared/api.ts` is the only
place that knows there is HTTP underneath, so `W1-T03`'s generated client can replace it without
touching a route.
